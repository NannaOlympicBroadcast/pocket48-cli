# snh48 写操作

本 skill 只管**写**。信封长什么样、成员怎么寻址、登录怎么处理，
全在配套的 `snh48-cli` skill 里（`pocket48-cli` 插件），需要时去看那边。

调用方式与只读插件一致，但**要用本插件自己的入口**（两个插件各带一份 CLI，
`$CLAUDE_PLUGIN_ROOT` 在本 skill 里指向 `pocket48-write`）：

```bash
node "$CLAUDE_PLUGIN_ROOT/cli.js" <命令>     # 作为插件安装时
node bin/snh48.js <命令>                      # 在 yaya_msg 仓库里开发时
```

下文示例简写成 `snh48 <命令>`，实际执行时替换成上面对应的那一条。
写操作还需要解除只读限制，见文末「只读限制」。

## 铁律：先复述，等确认，再执行

这些命令会真实送达对方、消耗用户的鸡腿/星币，而且基本撤不回来。
**即便用户在同一轮里已经把要做的事说得很清楚，仍要复述一次再发。**

固定四步：

1. **解析成员** — `snh48 member info <成员> --json`，确认是要操作的那个人。
   报「匹配到多位成员」就把候选列给用户让其确认，**绝不**自己挑一个。
   名册里确实有重名（比如分属 SNH48 与 GNZ48 的两位「李沁洁」），发错人无法挽回。
2. **查价**（仅翻牌）— `snh48 flip prices <成员> --json`，把价位念给用户。
   **不要**替用户挑贵的；用户没指定时说明默认价是多少。
3. **复述并等确认** — 念一遍「对谁、做什么、花多少」，问「确认吗？」。
   用户明确同意后才继续。含糊其辞就继续问，不要猜。
4. **执行并如实回报** — 成功时 `data.sent` 为 true；失败把 `error` 与 `hint` 原样转述。

## 命令表

| 命令 | 用法 | 代价 |
| --- | --- | --- |
| `dm send <成员> <内容>` | 发私信，成员之后的所有词拼成正文 | 免费，但对方收得到 |
| `flip ask <成员> <问题>` | 翻牌提问，`--price <价格ID>` 选价位、`--type` 选类型 | **花鸡腿/星币** |
| `flip delete <questionId>` | 撤回提问，`--type` 同上 | 免费 |
| `live send-gift <liveId> <giftId> [数量]` | 直播送礼，必须带 `--accept <成员用户ID>` | **花钱** |
| `member follow <成员>` / `member unfollow <成员>` | 关注 / 取关 | 免费 |
| `checkin` | 口袋签到 | 免费 |
| `account switch <用户ID>` | 大小号切换 | 改变后续所有命令的身份 |

撤回前先 `snh48 flip list --limit 20 --json` 确认要撤的是哪一条。

## 口袋 48 没有「往房间发消息」

`room *` 全是只读的。想对成员说话只有两条路：`dm send`（私信）和 `flip ask`（翻牌）。
用户说「给她房间发条消息」时，解释清楚并问他们要走哪条。

## 排错

- `尚未登录，缺少口袋 48 Token` → 先 `snh48 login status --json` 看状态，
  再把登录步骤交给用户。**写操作绝不能在没确认身份的情况下重试**——
  切错账号会用错人的鸡腿。
- 正文含空格是正常的；含引号或换行时用单引号把整段包起来传给 shell。
- 失败时先读 `hint` 再决定下一步，不要盲目重发——重发可能造成重复扣费。

## 只读限制

CLI 作为插件运行时**默认只读**，本 skill 里的每条写命令都会被拦下：

```
{"ok":false,"error":"只读模式下不允许执行「dm send」",
 "hint":"该命令会改动账号状态或消耗鸡腿/星币。确需执行时加 --allow-write…"}
```

这是有意为之的最后一道闸。**在按上面「铁律」拿到用户确认之后**，给该条命令加
`--allow-write`：

```bash
node "$CLAUDE_PLUGIN_ROOT/cli.js" dm send 杨冰怡 "生日快乐" --allow-write --json
```

只给当次要执行的那一条加。**不要**图省事去设 `SNH48_ALLOW_WRITE=1` 环境变量——
那会把整个会话的闸门都打开，后续任何一次误调都不会再被拦住。
